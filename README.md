# منظومة الإدارة العامة للمبيعات والشؤون التجارية — شركة البريقة لتسويق النفط

[![CI](https://github.com/brega-sells/Al-brega-Sells-Company/actions/workflows/ci.yml/badge.svg)](https://github.com/brega-sells/Al-brega-Sells-Company/actions/workflows/ci.yml)

منظومة عربية (RTL) تعمل من المتصفح وتُثبَّت كتطبيق على الهاتف والحاسوب، لإدارة عقود البريقة وكشوفات احتياجات الوزارة، ومهام الإدارات وتكليفاتها، والاجتماعات المغلقة، وخدمة الزبائن، وسجلات كل إدارة ومرفقاتها.

- **الرابط المباشر:** https://brega-sells.github.io/Al-brega-Sells-Company/
- **الاستضافة:** الصفحة على GitHub Pages، والبيانات والدخول على Firebase (مشروع `brega-sales`: Firestore + Authentication بالبريد وكلمة المرور).
- **دليل التشغيل للمالك ومدير النظام:** [docs/RUNBOOK.md](docs/RUNBOOK.md) · **سجل التغييرات:** [CHANGELOG.md](CHANGELOG.md) · **الأمان:** [docs/SECURITY.md](docs/SECURITY.md)

## الشاشات

| الشاشة | ما تفعله |
|---|---|
| لوحة المؤشرات | مؤشرات العقود والاحتياجات والطلبات، خط زمني لانتهاء العقود، كل مؤشر ينقلك إلى سجلاته |
| تحليل البيانات | مقارنات حسب النوع والمنطقة والدفعة مع طباعة وتصدير |
| خدمة الزبائن | طلبات وشكاوى برقم ومدة استجابة وتصعيد |
| الهيكل التنظيمي | شجرة الإدارات، مهام واختصاصات كل إدارة، سجلاتها ومرفقاتها، طباعة وتصدير |
| مركز مهام الإدارات والتكليفات | مهام كل إدارة ومصدرها الرسمي، إصدار التكليفات ومتابعتها (جديد → قيد التنفيذ → بانتظار الاعتماد → معتمد) مع مؤشرات أداء |
| الاجتماعات المغلقة | دعوة الإدارات، جدول الأعمال، المحضر والقرارات، الحضور، لا يراها إلا المدعوون |
| التقويم | مواعيد التكليفات والاجتماعات وانتهاء العقود وطلبات الزبائن، بالهجري والميلادي، تصدير `.ics` |
| عقود البريقة / التمديدات / كشوفات الاحتياجات / الدفعات / دليل الجهات | السجل الأساسي للعقود والوزارة (تُفتح من الهيكل التنظيمي) |
| الإعدادات | الصلاحيات، الاستيراد والتصدير، الإشعارات، التطبيق والتحديثات، صحة المنظومة (لمدير النظام) |

مزايا عامة: بحث شامل (`/`)، لوحة أوامر (`Ctrl+K`) تصل إلى أي شاشة أو إجراء أو سجل، اختصارات لوحة مفاتيح ومساعدة (`?`)، جرس إشعارات، واجهة إنجليزية اختيارية، مظهر فاتح/داكن، عمل دون اتصال، «ما الجديد» مع كل إصدار، إبلاغ تلقائي عن الأعطال برقم مرجعي.

## بنية الشيفرة

كل شيء ملفات ثابتة، بلا خطوة بناء:

| الملف | الدور |
|---|---|
| `index.html` | الصفحة الأساسية: التنسيقات، النواة (الحالة `S`، التنقل `go/render`، الشاشات الأساسية)، محوّل Firebase والدخول، الصلاحيات وسجل النشاط |
| `attach.js` | المرفقات والمسح الضوئي (PDF عبر `vendor/pdfjs`) |
| `meetings.js` | الاجتماعات المغلقة |
| `duties-data.js`, `duties.js` | مهام الإدارات (من اللوائح الرسمية) ومركز التكليفات |
| `notify.js` | جرس الإشعارات وتفضيلاته، وصفحة التقويم |
| `palette.js` | لوحة الأوامر، الاختصارات، المساعدة |
| `govern.js` | الحوكمة: مراجعة الصلاحيات وسجل الحسابات ومصفوفة الصلاحيات، مدد الاحتفاظ، الحجز القانوني، تاريخ التعديلات، ختم الاعتماد |
| `quality.js` | رقم الإصدار و«عن المنظومة» و«ما الجديد»، حاجز الأخطاء والإبلاغ، لوحة صحة المنظومة، لوحة التطبيق |
| `pwa.js`, `sw.js`, `manifest.webmanifest`, `icons/` | التثبيت كتطبيق، العمل دون اتصال، شريط التحديث |
| `version.js`, `releases.js` | رقم الإصدار وتاريخه، وملاحظات الإصدارات بالعربية |
| `firestore.rules` | قواعد الأمان (مصدر الحقيقة للصلاحيات) |
| `vendor/` | مكتبات Firebase وPDF.js مستضافة محليًا مع بصمات SRI |
| `tests/` | اختبارات القواعد (محاكي Firestore) واختبارات المتصفح (Playwright) |
| `scripts/check-syntax.mjs` | يتأكد أن كل الملفات تُفسَّر قبل النشر |
| `guides/` | أدلة الاستخدام والنشر |

الوحدات تُحمَّل بعد `index.html` وتلتف حول `render()`؛ `quality.js` آخرها كي يكون حاجز الأخطاء هو الأبعد.

> **بيانات حقيقية لا تُرفع إلى المستودع.** المستودع والموقع عامّان، فملف البيانات الأولية والعقود والكشوفات تبقى خارج git (انظر `.gitignore`)، ويستوردها مدير النظام من جهازه عبر «استيراد ملف البيانات الأولية».

## الصلاحيات

- الأدوار: `admin` (مدير النظام)، `editor` (محرر)، `viewer` (قارئ)، تُحفظ في `roles/<البريد>` مع اسم الإدارة `unit`.
- الدخول يتطلب بريدًا مؤكدًا. خروج تلقائي بعد 30 دقيقة من عدم النشاط، وإعادة إدخال كلمة المرور قبل تغيير الصلاحيات.
- كل إدارة ترى سجلاتها وتكليفاتها فقط؛ الإدارة العامة والمجلس ومدير النظام يرون الكل. الاجتماعات لا يراها إلا المدعوون.
- مدير النظام لا يستطيع تخفيض صلاحيته أو حذف حسابه بنفسه (حماية من إقفال النظام).

## الاختبارات

```bash
node scripts/check-syntax.mjs                       # كل الملفات تُفسَّر
cd tests && npm install
npm run rules                                        # قواعد Firestore في المحاكي → PASS 133 FAIL 0
npm run serve &  NODE_PATH=$PWD/node_modules npm run browser   # اختبارات المتصفح (XSS، المصادقة، التطبيق والإشعارات، لوحة الأوامر، الحوكمة)
```

تعمل نفس الاختبارات تلقائيًا على GitHub Actions مع كل طلب دمج ([ci.yml](.github/workflows/ci.yml)).

## النشر

1. ادمج إلى `main`؛ GitHub Pages ينشر الصفحة خلال دقيقة أو دقيقتين.
2. إذا تغيّر `firestore.rules` انشره من وحدة تحكم Firebase (Firestore → Rules → انسخ الملف → Publish). التفاصيل في [دليل التشغيل](docs/RUNBOOK.md).
3. ارفع رقم الإصدار في `version.js` وأضف ملاحظات في `releases.js` و`CHANGELOG.md`؛ المستخدمون يرون شريط «تحديث الآن» ثم «ما الجديد».
