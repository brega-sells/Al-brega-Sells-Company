نشر المنظومة على الإنترنت

رابط عام يفتح من أي جهاز، ببيانات مشتركة وحسابات للموظفين — مجانًا

تُنشر المنظومة في جزأين، كلاهما مجاني ويتم من المتصفح دون برامج:
  • Firebase (من Google): يحفظ البيانات المشتركة وحسابات الدخول.
  • GitHub Pages: يستضيف صفحة المنظومة ويعطيك الرابط العام.
الوقت المتوقع: 20 إلى 30 دقيقة. تحتاج حساب Google وحساب GitHub.

الجزء الأول: إنشاء قاعدة البيانات في Firebase

  1. افتح console.firebase.google.com وسجّل الدخول بحساب Google، ثم اضغط Create a project واكتب اسمًا (مثل contracts-system). يمكنك إيقاف Google Analytics، فلا حاجة له.
  2. تفعيل تسجيل الدخول: من القائمة الجانبية Build ← Authentication ← Get started ← تبويب Sign-in method ← اختر Email/Password ← فعّل الخيار الأول (Email/Password) ← Save.
  3. إنشاء قاعدة البيانات: Build ← Firestore Database ← Create database ← اختر موقعًا قريبًا (مثل europe-west) ← اختر Start in production mode ← Create.
  4. قواعد الحماية: في صفحة Firestore افتح تبويب Rules، احذف كل ما فيه، وانسخ مكانه محتوى الملف firestore.rules المرفق كاملًا، ثم Publish.
    هذه القواعد تمنع أي شخص من قراءة البيانات أو تعديلها ما لم يكن له حساب وصلاحية ممنوحة من المدير.
  5. تسجيل نفسك كمدير: في تبويب Data اضغط Start collection:
    • Collection ID: roles
    • Document ID: بريدك الإلكتروني بأحرف صغيرة (مثل name@gmail.com) — نفس البريد الذي ستسجّل به الدخول في المنظومة لاحقًا.
    • أضف حقلين: role = admin (نوع string)، وname = اسمك.
    • Save.
  6. نسخ إعدادات الاتصال: اضغط رمز الترس بجانب Project Overview ← Project settings ← انزل إلى Your apps ← اضغط رمز الويب </> ← اكتب أي اسم ← Register app (لا تفعّل Hosting).
    سيظهر كود فيه const firebaseConfig = { apiKey: "...", ... }. افتح الملف firebase-config.js المرفق بمحرر نصوص (Notepad)، وانسخ القيم مكان القيم الموجودة: apiKey وauthDomain وprojectId وstorageBucket وmessagingSenderId وappId. احفظ الملف.

الجزء الثاني: نشر الصفحة على GitHub Pages

  1. افتح github.com وسجّل الدخول (أو أنشئ حسابًا مجانيًا)، ثم اضغط + ← New repository. اكتب اسمًا مثل contracts-system، واختر Public، واضغط Create repository.
    الملفات المنشورة عامة، لكنها لا تحوي أي بيانات؛ البيانات كلها في Firebase ومحمية بالقواعد وكلمات المرور.
  2. اضغط uploading an existing file (أو Add file ← Upload files) واسحب هذه الملفات الثلاثة: index.html وfirebase-config.js (بعد تعديله) و.nojekyll، ثم Commit changes.
  3. افتح Settings (أعلى المستودع) ← من القائمة الجانبية Pages ← تحت Branch اختر main و/ (root) ← Save.
  4. بعد دقيقة أو دقيقتين يظهر في نفس الصفحة رابط المنظومة بالشكل:
    https://اسم-حسابك.github.io/contracts-system/
    هذا هو الرابط الذي ترسله للموظفين.
  5. خطوة ضرورية: ارجع إلى Firebase ← Authentication ← تبويب Settings ← Authorized domains ← Add domain ← اكتب اسم-حسابك.github.io. بدون هذه الخطوة يرفض Firebase تسجيل الدخول من الرابط.

الجزء الثالث: أول استخدام

  1. افتح الرابط، واضغط أنشئ حسابًا، وسجّل بنفس البريد الذي وضعته في مجموعة roles، مع كلمة مرور (6 أحرف على الأقل).
  2. ستدخل كمدير، وتظهر لك رسالة «قاعدة البيانات فارغة» مع زر تحميل البيانات الأولية. اضغطه مرة واحدة، فتُحمَّل العقود (39) والكشوفات (393).
  3. إضافة الموظفين: يفتح كل موظف الرابط ويضغط «أنشئ حسابًا» ببريده. ثم تدخل أنت إلى الإعدادات ← المستخدمون والصلاحيات، وتكتب بريده وتختار صلاحيته (محرر / مشاهد) وتضغط حفظ. من تلك اللحظة يستطيع الدخول.

ملاحظات

  • الخطة المجانية في Firebase تكفي بكثير لهذا الحجم من البيانات والمستخدمين (50 ألف قراءة يوميًا).
  • النسخ الاحتياطي: صدّر «نسخة كاملة» من صفحة الإعدادات دوريًا واحفظها لديك.
  • عند تحديث المنظومة لنسخة أحدث، ارفع index.html الجديد فقط إلى GitHub (استبدل القديم). البيانات لا تتأثر.
  • إرفاق ملفات PDF داخل بطاقة العقد غير مفعّل في هذه النسخة؛ يمكن كتابة مسار الملف أو رابطه في خانته.
  • إذا ظهرت رسالة «هذا النطاق غير مُصرّح به»: لم تُنفَّذ الخطوة 5 من الجزء الثاني.
  • إذا ظهرت «لم تُمنح له صلاحية بعد» لك أنت: تأكد أن اسم المستند في roles يطابق بريدك تمامًا بأحرف صغيرة.
