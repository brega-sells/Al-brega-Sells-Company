# الأمان في منظومة البريقة

ملخص الضوابط المطبقة وكيفية التحقق منها. التفاصيل التشغيلية في [RUNBOOK.md](RUNBOOK.md).

## نموذج التهديد باختصار
الصفحة عامة على GitHub Pages، لذا الحماية الفعلية كلها في **Firebase Authentication** و**قواعد Firestore**. إعدادات Firebase في الصفحة ليست سرًا (هذا تصميم Firebase)؛ السر هو القواعد.

## الضوابط

| الطبقة | الضابط | أين |
|---|---|---|
| الهوية | دخول بالبريد وكلمة المرور (8+)، **البريد مؤكد شرط لكل قراءة أو كتابة** | `index.html` (المحوّل) + `signedIn()` في القواعد |
| الجلسة | خروج تلقائي بعد 30 دقيقة من عدم النشاط؛ إعادة إدخال كلمة المرور قبل تغيير الصلاحيات | `IDLE_MS`, `window.__reauth` |
| الصلاحيات | أدوار `admin/editor/viewer` + إدارة `unit`؛ كل إدارة ترى سجلاتها وتكليفاتها فقط؛ الاجتماعات للمدعوين فقط؛ المرفقات ترث صلاحية سجلها (`scope`: الكل، أو إدارات بعينها، أو من يرى الاجتماع) ويحذفها رافعها أو مدير النظام | `firestore.rules` |
| حماية المدير | مدير النظام لا يحذف نفسه ولا يخفّض صلاحيته؛ الأدوار من قائمة مغلقة وبمفاتيح محددة | `roles` في القواعد |
| سلامة البيانات | حدود أحجام النصوص والقوائم لكل مجموعة؛ `createdBy` لا يتغير؛ سجل النشاط للإضافة فقط، وكل كتابة في المجموعات المشتركة تُرفض ما لم تُحفظ مع قيدها في الدفعة نفسها، والقيد مختوم بوقت الخادم | القواعد |
| المتصفح | CSP (`script-src 'self' 'unsafe-inline' https://apis.google.com` لنافذة الدخول بحساب Google، ومصادر اتصال محددة)، منع التضمين في إطارات، `referrer` مقيد، كل القيم تمر عبر `esc()` | رأس `index.html` |
| سلسلة التوريد | مكتبات Firebase وPDF.js مستضافة محليًا في `vendor/` مع بصمات SRI | `vendor/README.md` |
| الحوكمة | مراجعة صلاحيات كل 90 يومًا مع سجل حسابات ومصفوفة صلاحيات؛ حجز قانوني يمنع الحذف؛ تاريخ تعديلات لكل سجل؛ ختم اعتماد SHA-256 للتكليفات | `govern.js`, `records` في القواعد |
| التشغيل | بلاغات الأخطاء في `clientErrors` بلا بيانات حساسة، يقرؤها مدير النظام فقط؛ تفضيلات المستخدم `prefs` لصاحبها فقط | `quality.js`, `notify.js` |

## ما ليس مطبقًا (قرار واعٍ)
- `unsafe-inline` في CSP لازم لأن النواة داخل `index.html`؛ تعويضه بالهروب الصارم لكل القيم واختبار XSS تلقائي.
- التحقق بخطوتين يحتاج Identity Platform (Blaze). راجع §7 في دليل التشغيل.

## التحقق
- `cd tests && npm run rules` → 133 حالة تغطي كل مجموعة ودور.
- `node tests/browser/xss.js` (و`ROLE=w`) → حمولة XSS في كل حقل من كل مجموعة، وكل شاشة وتبويب ولوحة جانبية ونافذة طباعة: `hits: []`.
- `node tests/browser/auth.js` → بوابة التحقق من البريد، إعادة المصادقة، منع تخفيض الذات، نطاق الإدارة، الخروج التلقائي.

## الإبلاغ عن ثغرة
راسل مالك المنظومة على بريده الرسمي مع الرقم المرجعي إن وُجد. لا تنشر التفاصيل علنًا قبل الإصلاح.
