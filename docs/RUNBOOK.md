| متى | ماذا | أين |

## 2. النشر وتحديث المنظومة

النشر يتم بدمج التغيير إلى الفرع `main`؛ GitHub Pages ينشر خلال 1–2 دقيقة.

1. افتح طلب الدمج على GitHub وتأكد أن فحوصات **CI** خضراء (تُفسَّر الملفات، تنجح اختبارات القواعد والمتصفح).
2. اضغط **Merge**.
3. إذا كان التغيير يمس `firestore.rules` نفّذ §3 **فورًا** (الصفحة الجديدة قد تحتاج القواعد الجديدة).
4. افتح الرابط المباشر. المستخدمون الذين فتحوا المنظومة سابقًا يرون شريط «يتوفر إصدار جديد → تحديث الآن»، ثم نافذة «ما الجديد» مرة واحدة.
5. تحقق من رقم الإصدار أسفل القائمة.

**رفع رقم الإصدار:** عدّل `APP_VERSION` و`APP_DATE` في `version.js`، وأضف بندًا في `releases.js` (يراه المستخدمون) و`CHANGELOG.md` (للفريق التقني). الأرقام: `كبير.متوسط.صغير` — كبير لتغيير في طريقة العمل، متوسط لميزة جديدة، صغير لإصلاح.

## 3. نشر قواعد الأمان (Firestore Rules)

القواعد هي ما يحدد من يقرأ ومن يكتب. الصفحة لا تنشرها تلقائيًا.

1. افتح https://console.firebase.google.com/project/brega-sales/firestore/rules
2. افتح ملف `firestore.rules` من المستودع (الفرع `main`) وانسخ محتواه كاملًا.
3. الصقه مكان القواعد الحالية، ثم اضغط **Publish**.
4. تحقق: سجّل الدخول بحساب محرر من إدارة ما وتأكد أنه يرى سجلات إدارته فقط، وأن مدير النظام يرى لوحة «صحة المنظومة».

> في المستودع نسخة من القواعد اختُبرت بـ 133 حالة في المحاكي. لا تعدّل القواعد يدويًا في وحدة التحكم؛ عدّل الملف في المستودع ثم انشره.

## 4. إدارة الحسابات والصلاحيات

**إضافة موظف:**
1. يفتح الموظف الرابط ويختار «إنشاء حساب» ببريده الرسمي وكلمة مرور (8 أحرف فأكثر)، ثم يؤكد بريده من رسالة التحقق.
   أو يضغط «الدخول بحساب Google» ويختار بريد Gmail؛ عندها يُعدّ البريد مؤكدًا فورًا دون رسالة. (يلزم تفعيل Google مرة واحدة: Firebase Console → Authentication → Sign-in method → Google → Enable → Save.)
2. مدير النظام: الإعدادات → الصلاحيات → أدخل البريد والاسم والدور والإدارة → حفظ (سيُطلب منك كلمة مرورك مرة أخرى).
3. الأدوار: **قارئ** يشاهد فقط · **محرر** يضيف ويعدّل في نطاق إدارته · **مدير النظام** كل شيء. اختر الإدارة بدقة لأنها تحدد ما يراه.

**إيقاف موظف غادر:** احذف دوره من الإعدادات → الصلاحيات (يفقد الوصول فورًا)، ثم عطّل حسابه من Firebase Console → Authentication → Users → ⋮ → Disable account.

**كلمة مرور منسية:** من شاشة الدخول «نسيت كلمة المرور»، أو من Firebase Console → Authentication → ⋮ → Reset password.

**مدير نظام احتياطي:** يجب أن يوجد دائمًا حسابا مدير نظام على الأقل. المنظومة تمنع مدير النظام من حذف نفسه أو تخفيض صلاحيته.

**مراجعة الصلاحيات الفصلية:** الإعدادات → «مراجعة الصلاحيات الدورية»: تعرض كل حساب مع آخر نشاط والحسابات الخاملة. راجعها مع رؤساء الإدارات، احذف ما لم يعد لازمًا من لوحة الصلاحيات، ثم «اعتماد المراجعة» (يُطلب كلمة المرور ويُسجَّل في سجل النشاط). «تصدير سجل الحسابات» يعطي ملف CSV للمحضر، و«مصفوفة الصلاحيات» تبيّن ما يستطيعه كل دور. تظهر المنظومة تنبيهًا إذا مضى أكثر من 90 يومًا.

## 5. النسخ الاحتياطي والاستعادة

- **أسبوعيًا:** الإعدادات → «تصدير نسخة كاملة» → ملف Excel بكل الأوراق. احفظه في مكان آمن (محرك شبكي + نسخة خارجية).
- **المرفقات** تُخزَّن داخل Firestore (مجموعة `files`) وتدخل في نسخة Firebase الاحتياطية، لا في Excel.
- **نسخة Firestore كاملة (اختياري، يحتاج خطة Blaze):** Firebase Console → Firestore → Import/Export → Export إلى حاوية تخزين. يمكن جدولتها شهريًا.
- **الاستعادة من Excel:** الإعدادات → استيراد → اختر الملف. الاستيراد يضيف ويحدّث حسب رقم العقد/المعرف ولا يحذف.
- **اختبار الاستعادة:** مرة كل 6 أشهر، استورد النسخة في مشروع Firebase تجريبي وتأكد أن الأرقام تطابق.

## 6. عند حدوث مشكلة

| العرض | السبب المحتمل | الإجراء |
|---|---|---|
| «حدث خطأ غير متوقع» برقم مرجعي E-xxxxxx | خطأ في شاشة واحدة | اضغط «إعادة المحاولة». إن تكرر، أرسل الرقم المرجعي؛ تفاصيله في الإعدادات → صحة المنظومة |
| «لا تملك صلاحية» أو شاشة فارغة بعد الدخول | لم يُحدد دور للبريد، أو البريد غير مؤكد | تحقق من الصلاحيات (§4) وأن المستخدم أكد بريده |
| المستخدم يرى سجلات إدارة أخرى أو لا يرى سجلاته | الإدارة `unit` خاطئة في دوره | صحّح الإدارة في الإعدادات → الصلاحيات |
| التحديث لا يظهر | نسخة قديمة مخزنة | الإعدادات → التطبيق والتحديثات → «التحقق من وجود تحديث»، أو «إصلاح التطبيق» (يمسح النسخة المحلية فقط) |
| «أنت غير متصل» دائمًا | الإنترنت أو حجب نطاقات Google | جرّب شبكة أخرى؛ المنظومة تحتاج `*.googleapis.com` و`*.firebaseapp.com` |
| الدخول يفشل للجميع | تعطّل Firebase أو تجاوز الحصة | https://status.firebase.google.com ثم Firebase Console → Usage |
| تغيّرت القواعد فتوقفت كتابة ما | قواعد غير منشورة أو خاطئة | انشر قواعد `main` (§3)؛ للرجوع، وحدة التحكم تحتفظ بتاريخ القواعد (Rules → History → Restore) |

**الرجوع إلى إصدار سابق للصفحة:** في GitHub → Commits على `main` → اختر الإصدار السابق → «Revert» ثم ادمج؛ أو Releases/Tags إن وُجدت. ثم انشر قواعد ذلك الإصدار إن كانت مختلفة.

## 7. حدود الخطة المجانية (Spark) وما يحتاج Blaze

يعمل كل ما في المنظومة على الخطة المجانية. التالية تحتاج ترقية إلى Blaze (الدفع حسب الاستخدام، عادة بضعة دولارات شهريًا لهذا الحجم) لأنها تحتاج Cloud Functions أو خدمات مدفوعة:

- إشعارات الدفع إلى الهاتف والمنظومة مغلقة (FCM) وإرسال رسائل البريد الدورية.
- التقارير المجدولة (تقرير أسبوعي يصل بالبريد).
- المساعد الذكي داخل المنظومة والبحث في محتوى المسح الضوئي (OCR).
- التحقق بخطوتين (MFA) عبر Identity Platform.
- النسخ الاحتياطي التلقائي المجدول لقاعدة البيانات.

عند الترقية: Firebase Console → Upgrade → Blaze، وضع **ميزانية تنبيه** (Budget alert) بـ 10 دولارات.

## 8. جهات الاتصال التقنية

- الشيفرة والوثائق: المستودع أعلاه (ملف `README.md` وهذا الدليل و`CHANGELOG.md`).
- التحقق من الأمان قبل أي تغيير على القواعد: `cd tests && npm run rules`.
